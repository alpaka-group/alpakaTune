# Workflow integration tests

Build with `-DalpakaTune_BUILD_TESTING=ON`, then run:

```sh
ctest --test-dir build -L integration --output-on-failure
```

The suite checks complete numerical results throughout each application loop:

| Workflow | Workload | Contracts exercised |
| --- | --- | --- |
| Pipeline | 96 batches of 131,071 integers through two kernels | Independent tuners, 16 and 4 candidates, runtime and compile-time parameters, queued warm-ups, changing arguments and alternating allocations, exact full-array results, terminal replay without additional samples |
| Heat diffusion | 64 steps on a 257 × 193 grid | Ping-pong buffers, fixed boundaries, six launch geometries, non-divisible extents, every cell checked against an independent CPU reference at every step |
| Quality-controlled quadrature | 32 batches of 1,025 integrals with 8, 64, or 512 midpoint samples | Real elapsed application metric, full-array analytical `atan` reference, invalidation of inaccurate candidates, valid winner replay |
| Persistence | Pipeline training and replay in separate processes | Histories generated by real kernel runs, both tuner contexts restored, fresh input data and allocations, read-only replay preserves both history files byte for byte |

Persistence cases are registered only when persistence is enabled. CTest fixtures
run training before replay, including when selecting only the replay test.
The three in-memory workflows also work with persistence disabled.

The executable uses the host device by default. Its workload functions accept a
deduced device and executor; a CUDA build can run the same assertions on a GPU:

```sh
build/tests/alpakaTune_workflow_tests pipeline --cuda
build/tests/alpakaTune_workflow_tests stencil --cuda
build/tests/alpakaTune_workflow_tests quality --cuda
build/tests/alpakaTune_workflow_tests pipeline stage build/gpu-workflow-history --cuda
build/tests/alpakaTune_workflow_tests pipeline replay build/gpu-workflow-history --cuda
```

Requesting CUDA fails if it was not compiled in or no CUDA device is available.
GPU execution is explicit so compiler-only CI jobs do not require GPU hardware.

## Adaptive Pi objective tests

```sh
ctest --test-dir build -R alpakaTune_adaptive_pi_tests --output-on-failure
```

These cases use available devices for each enabled backend. They check tile-area
conservation, geometric Pi bounds, sampling only at the final depth, both
objectives, and valid winner replay. Zero runtime or zero-error limits test the
case where no candidate is valid.

For the 10 ms acceptance limit, the inspection hook supplies deterministic 5 ms
and 20 ms durations. Geometry and accuracy checks still use real device results;
the timing fixture keeps acceptance tests independent of sanitizer overhead,
backend startup, and runner speed. The example executable uses measured durations.

## Installed-package test

```sh
cmake -S . -B build -DalpakaTune_BUILD_TESTING=ON -DalpakaTune_INSTALL_TEST=ON
cmake --build build
ctest --test-dir build -R alpakaTune_install_consumer --output-on-failure
```

The test installs the build into a scratch prefix below the build directory. It then configures
`tests/install_consumer` against that prefix with `find_package(alpakaTune CONFIG REQUIRED)`, builds the first-tuner
tutorial as the consumer, and runs it. The consumer project has no FetchContent fallback.

## Naming checks with clang-tidy

```sh
cmake -S . -B build-tidy -DCMAKE_CXX_COMPILER=clang++ -DalpakaTune_CLANG_TIDY=ON \
  -DalpakaTune_BUILD_TESTING=ON -DalpakaTune_BUILD_EXAMPLES=ON
cmake --build build-tidy
```

`alpakaTune_CLANG_TIDY` requires Clang and a matching `clang-tidy`. The build then runs clang-tidy with the
repository's `.clang-tidy` on every public header and on the configured tests, examples, and documentation examples.
The rules are alpaka's identifier-naming rules, and a finding fails the build.

## Line coverage

```sh
cmake -S . -B build-coverage -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="--coverage -Og" \
  -DalpakaTune_BUILD_TESTING=ON -Dalpaka_DEP_OMP=OFF
cmake --build build-coverage
ctest --test-dir build-coverage
gcovr --root . --filter include/alpakaTune/ build-coverage/tests
```

The report covers the public headers as exercised by the tests. Counts for heavily templated headers include every
instantiation. Keep OpenMP disabled: instrumented OpenMP kernels are slow enough to exceed the test timeouts.
